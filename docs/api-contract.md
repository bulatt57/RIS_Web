## 1. Таблица маршрутов API

| Метод и путь | Тело (что прислать) | Успех | Возможная ошибка |
|--------------|---------------------|-------|------------------|
| `GET /api/assignments` | — *(опционально query: `status`, `departmentId`, `assigneeUserId`, `dueDate`)* | `200 OK`, массив объектов или `[]` | — |
| `GET /api/assignments/{id}` | — | `200 OK`, один объект поручения | `404 Not Found` (если `id` не найден) |
| `POST /api/assignments` | `title`, `departmentId`, `description` *(опционально `dueDate`)* | `201 Created`, в ответе `id`, `number`, `status: "New"` | `400 Bad Request` (ошибка валидации), `403 Forbidden` (не руководитель) |
| `PATCH /api/assignments/{id}/assignee` | `assigneeUserId` | `200 OK`, обновлённый объект | `400 Bad Request`, `403 Forbidden`, `404 Not Found` |
| `PATCH /api/assignments/{id}/status` | `status` *(и `cancelReason` при отмене)* | `200 OK`, обновлённый объект | `403 Forbidden` (чужое поручение), `404 Not Found`, `409 Conflict` (недопустимый переход статуса) |
| `GET /api/departments` | — | `200 OK`, список подразделений ЕЦУиМС для выпадающего списка | — |
| `GET /api/users` | — | `200 OK`, список сотрудников (исполнителей) для назначения | — |

## 2. Важные архитектурные ограничения контракта

1. **Поля, формируемые сервером:** при создании поручения (`POST /api/assignments`) клиент **не присылает** `id`, `number`, `status` и исполнителя (`assigneeUserId`). Эти поля генерирует и выставляет сервер (`status = "New"`, `number = "ПОР-2026-0001"`).
2. **Два разных `PATCH`:** назначение исполнителя (`PATCH /api/assignments/{id}/assignee`) и смена статуса (`PATCH /api/assignments/{id}/status`) разделены на два независимых маршрута, чтобы разграничить права ролей (назначает только руководитель, а переводит в работу назначенный исполнитель) и исключить случайную перезапись полей.
3. **Запрет `DELETE`:** метод `DELETE` в API отсутствует. Отмена поручения выполняется переводом в статус `Cancelled` через `PATCH /api/assignments/{id}/status`.
4. **Чистые REST-пути:** пути вида `/api/assignments/create` или `/api/assignments/update` не используются — действие определяется HTTP-методом (`POST`, `PATCH`, `GET`).
5. **Пустой список — не ошибка:** если по фильтру или в базе ещё нет поручений, `GET /api/assignments` возвращает код `200 OK` и пустой массив `[]`, а не `404`.

## 3. Примеры JSON-запросов и ответов

### 3.1. Создание поручения (Критерий 1)
**Запрос:** `POST /api/assignments`
```json
{
  "title": "Проверить оптическую линию на узле доступа",
  "departmentId": 1,
  "description": "Выполнить диагностику затухания сигнала после плановых работ и приложить сводку",
  "dueDate": "2026-10-25T15:00:00Z"
}
```

**Ответ (`201 Created`):**
```json
{
  "id": 17,
  "number": "ПОР-2026-0001",
  "title": "Проверить оптическую линию на узле доступа",
  "departmentId": 1,
  "description": "Выполнить диагностику затухания сигнала после плановых работ и приложить сводку",
  "status": "New",
  "createdByUserId": 1,
  "assigneeUserId": null,
  "dueDate": "2026-10-25T15:00:00Z",
  "createdAt": "2026-10-17T09:30:00Z",
  "startedAt": null,
  "closedAt": null,
  "cancelReason": null
}
```

**Ответ при ошибке валидации (`400 Bad Request`):**
```json
{
  "error": "Validation failed",
  "details": [
    "Поле title должно содержать от 5 до 80 символов",
    "Поле departmentId должно быть положительным числом (> 0)"
  ]
}
```

---

### 3.2. Назначение исполнителя отдельным действием (Критерий 2)
**Запрос:** `PATCH /api/assignments/17/assignee`
```json
{
  "assigneeUserId": 5
}
```

**Ответ (`200 OK`):**
```json
{
  "id": 17,
  "number": "ПОР-2026-0001",
  "title": "Проверить оптическую линию на узле доступа",
  "departmentId": 1,
  "status": "New",
  "assigneeUserId": 5
}
```

---

### 3.3. Перевод поручения в работу исполнителем (Критерий 3)
**Запрос:** `PATCH /api/assignments/17/status`
```json
{
  "status": "InProgress"
}
```

**Ответ (`200 OK`):**
```json
{
  "id": 17,
  "number": "ПОР-2026-0001",
  "status": "InProgress",
  "startedAt": "2026-10-17T10:15:00Z"
}
```

**Ответ при нарушении правил перехода статуса (`409 Conflict`):**
```json
{
  "error": "Conflict",
  "message": "Нельзя перевести закрытое поручение (Closed) обратно в статус InProgress"
}
```

**Ответ при попытке изменить чужое поручение (`403 Forbidden`):**
```json
{
  "error": "Forbidden",
  "message": "Исполнитель может менять статус только своих поручений"
}
```
