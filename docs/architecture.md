## 1. Трёхузловая схема архитектуры

```text
Vue 3 + Vite                    ASP.NET Core                     PostgreSQL
localhost:5173  ──────────────► localhost:5000  ───────────────► обычно :5432
                 HTTP (JSON)                     запросы к БД
                 Пример:                         (SQL / EF Core)
                 POST /api/assignments
```

**архитектура web-ИС семестра**

Это и есть архитектура web-ИС семестра — три узла, две связи, один источник правды о поручениях.

---

## 2. Назначение узлов

| Узел | Технология | Порт в разработке | Роль в системе TaskControl |
|------|------------|-------------------|----------------------------|
| Клиент (браузер) | Vue 3 + Vite | `5173` | Отрисовывает экраны (вход, реестр поручений ЕЦУиМС, форма создания и карточка поручения) и отправляет HTTP-запросы к серверу. |
| Сервер (Backend API) | ASP.NET Core Web API | `5000` | Проверяет JWT-аутентификацию, права ролей (`Manager`, `Executor`, `Viewer`), валидирует поля, генерирует `id`, номер `ПОР-2026-0001` и начальный статус `New`, контролирует переходы статусов (`New`, `InProgress`, `Closed`, `Cancelled`). |
| База данных | PostgreSQL | `5432` | Надёжно хранит таблицы поручений (`Assignments`), подразделений ЕЦУиМС (`Departments`) и сотрудников (`Users`) на диске (выполнение НФТ-1). |

## 3. Пример полного сквозного HTTP-запроса (Vue → ASP.NET Core)

Когда руководитель ЕЦУиМС создаёт новое поручение на клиенте (`http://localhost:5173`), браузер отправляет HTTP-запрос на сервер (`http://localhost:5000`):

- **Метод и путь:** `POST http://localhost:5000/api/assignments`
- **Тело запроса (JSON):**
```json
{
  "title": "Проверить оптическую линию на узле доступа",
  "departmentId": 1,
  "description": "Выполнить диагностику затухания сигнала после плановых работ и приложить сводку",
  "dueDate": "2026-10-25T15:00:00Z"
}
```
- **Ответ сервера при успехе (`201 Created`):**
```json
{
  "id": 17,
  "number": "ПОР-2026-0001",
  "title": "Проверить оптическую линию на узле доступа",
  "departmentId": 1,
  "description": "Выполнить диагностику затухания сигнала после плановых работ и приложить сводку",
  "status": "New",
  "createdByUserId": 1,
  "assigneeUserId": null,
  "dueDate": "2026-10-25T15:00:00Z",
  "createdAt": "2026-10-17T09:30:00Z"
}
```

## 4. Почему браузер не обращается к PostgreSQL напрямую

Прямой стрелки от браузера (`Vue :5173`) к базе данных (`PostgreSQL :5432`) **нет и быть не должно**:
1. **Безопасность:** если открыть доступ к СУБД из браузера, любой пользователь сможет увидеть учётные данные подключения, прочитать или удалить чужие поручения напрямую.
2. **Контроль бизнес-правил:** только сервер (`ASP.NET Core :5000`) гарантирует соблюдение правил из ЛР1 — например, что исполнитель (`Executor`) не может создать поручение (ФТ-9), не может сменить статус чужой записи (ФТ-10) и что статус меняется строго по разрешённым переходам.
3. **Единый источник правды:** сервер централизованно присваивает машинный `id`, формирует уникальный человеческий номер `ПОР-2026-0001` и фиксирует время в UTC (НФТ-4).
