## 1. Цель работы

Разрезать каркас клиентского приложения на компоненты и страницы, подключить `vue-router`: шапка `AppHeader` остаётся на месте снаружи `router-view`, маршруты `/`, `/new`, `/login` открываются как по ссылкам меню, так и ручным вводом в адресную строку, таблица `TicketTable.vue` получает данные через `props`, а единственный общий массив записей лежит в `ticketsStore.js`.

### 2.2. Дерево каталога `frontend/src/`

```text
frontend/src/
├── main.js                ← подключение createRouter (app.use(router))
├── App.vue                ← корневой каркас: AppHeader + router-view
├── router.js              ← конфигурация трёх маршрутов (/, /new, /login)
├── ticketsStore.js        ← единственный общий массив items (ref)
├── assets/                ← статические ресурсы
├── components/
│   ├── AppHeader.vue      ← шапка приложения с навигацией <router-link>
│   └── TicketTable.vue    ← компонент таблицы с входным параметром defineProps({ items })
└── pages/
    ├── TicketList.vue     ← страница списка поручений (маршрут /)
    ├── TicketNew.vue      ← страница создания поручения (маршрут /new)
    └── Login.vue          ← страница входа в систему (маршрут /login)
```

### 2.3. Схема «AppHeader снаружи, router-view внутри»

```text
App.vue
├── AppHeader        ← всегда виден на всех страницах (снаружи router-view)
└── main
    └── router-view  ← сюда vue-router подставляет страницу текущего маршрута:
                        • /       → pages/TicketList.vue (внутри вызывает <TicketTable :items="items" />)
                        • /new    → pages/TicketNew.vue
                        • /login  → pages/Login.vue
```

## 4. Ответы на вопросы для устной защиты (§6 методички)

### 1. Чем `/new` отличается от `POST /api/tickets` (в нашей теме — `POST /api/assignments`)?
- `/new` — это клиентский маршрут внутри браузера (`vue-router`). Он просто переключает экран в `router-view` и показывает пользователю пустую HTML-форму `TicketNew.vue`, но сам по себе никаких данных на сервер не отправляет и запись не создаёт.
- `POST /api/assignments` (или `POST /api/tickets` в примере курса) — это сетевой HTTP-запрос от клиента к серверу `ASP.NET Core :5000` с JSON-телом, который валидирует данные и создаёт новую запись в базе данных.

### 2. Кто владеет массивом записей?
Единственным источником и владельцем массива записей в клиентском приложении является модуль `src/ticketsStore.js`, где объявлен реактивный массив `export const items = ref([...])`. Страница `TicketList.vue` импортирует эту ссылку из `ticketsStore.js` и передаёт её вниз компоненту таблицы.

### 3. Зачем таблице `props`?
Входные параметры (`props`) делают компонент `TicketTable.vue` независимым и переиспользуемым: таблица отвечает только за отрисовку переданных ей строк и не знает, откуда пришли данные (из тестового `ticketsStore.js`, из отфильтрованного списка или в будущем с сервера). Благодаря `props` данные текут сверху вниз (от страницы `TicketList.vue` к компоненту `TicketTable.vue`), а сам массив не дублируется.

### 4. Почему шапка должна быть снаружи `router-view`?
Шапка (`<AppHeader />`) является общей частью каркаса для всех экранов приложения. Когда она размещена в `App.vue` выше `<router-view />`, при переходе между `/`, `/new` и `/login` меняется только содержимое внутри `router-view`, а шапка остаётся на месте. Если бы шапка была внутри каждой страницы, её код пришлось бы дублировать в трёх файлах (`TicketList.vue`, `TicketNew.vue`, `Login.vue`), и при любой правке меню пришлось бы менять три файла вместо одного.
