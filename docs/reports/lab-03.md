## 1. Цель работы

В основном репозитории проекта поднять клиентское приложение на `Vue 3` (JavaScript) и `Vite` в папке `/frontend` так, чтобы по инструкции из `README.md` открывались три семантически верных экрана (список поручений, создание поручения, вход) на порту `http://localhost:5173`.

---

## 2. Что реализовано в `/frontend`

1. **Каркас приложения (`Vue 3 + Vite`, JavaScript):**
   - Настроен конфигурационный файл `frontend/vite.config.js` на порт `5173`.
   - В однофайловом компоненте `frontend/src/App.vue` реализовано реактивное состояние `screen` (`'list'`, `'new'`, `'login'`) с помощью `ref` и условного рендеринга `v-if` / `v-else-if`.
2. **Экран «Список поручений» (`screen === 'list'`):**
   - Оформлен семантической таблицей `<table>` внутри `<main>`.
   - Через директиву `v-for="item in items" :key="item.id"` выводятся тестовые записи поручений (`ПОР-2026-0001`, `ПОР-2026-0002` и др.) с полями `id`, `number`, `title`, `departmentId` и статусами курса (`New`, `InProgress`, `Closed`, `Cancelled`).
3. **Экран «Создание поручения» (`screen === 'new'`):**
   - Оформлен тегом `<form @submit.prevent>`.
   - Содержит три поля с именами из контракта API ЛР2 (`title`, `departmentId`, `description`), каждое поле связано со своим `<label for="...">`. Первое поле (`#title`) автоматически получает фокус (`autofocus`).
4. **Экран «Вход» (`screen === 'login'`):**
   - Оформлен тегом `<form @submit.prevent>` с полями `login`, `password`, связанными подписями `<label>` и кнопкой отправки.

## 4. Ответы на вопросы для устной защиты

### 1. Зачем нужен Vite, если браузер уже показывает HTML?
Браузер не умеет напрямую выполнять однофайловые компоненты `.vue` (в которых объединены `<script setup>`, `<template>` и `<style scoped>`). Сборщик и сервер разработки **Vite** на лету компилирует `.vue`-файлы в стандартный JavaScript и CSS, которые понимает браузер, а также обеспечивает мгновенное обновление страницы при изменении кода (Hot Module Replacement) на `http://localhost:5173`.

### 2. Чем `v-for` лучше трёх строк, скопированных вручную?
Директива `v-for` строит строки таблицы динамически по массиву данных (`items`). Если данных станет 50 или они придут с сервера `ASP.NET Core` в следующих лабораторных работах, разметку `<tr>` менять не придётся — Vue сам отрисует нужное количество строк и обновит только изменившиеся элементы благодаря атрибуту `:key="item.id"`.

### 3. Зачем полю нужен `<label>`?
Тег `<label for="...">`, связанный с `id` поля ввода:
1. Делает интерфейс понятным для человека (видно, что именно нужно ввести и какие ограничения у поля, даже когда внутри `input` уже набран текст).
2. Улучшает удобство использования: при клике мышью по тексту `<label>` курсор автоматически ставится в связанное поле ввода.
3. Обеспечивает доступность (accessibility): программы чтения с экрана зачитывают подпись `<label>`, когда пользователь переходит на поле клавишей `Tab`.

### 4. Почему `node_modules` не кладут в Git?
Папка `node_modules` содержит тысячи скачанных библиотечных файлов и весит десятки или сотни мегабайт. Хранить её в Git бессмысленно и вредно: она раздувает репозиторий и замедляет клонирование. Вместо этого в Git хранят лёгкие файлы `package.json` и `package-lock.json`, по которым любой разработчик на своей машине может за несколько секунд точно воспроизвести всю папку `node_modules` одной командой `npm install`.
